# Cross-maturity repair of CIR mu and theta

This folder holds the legacy NS/NSS repair outputs for the rolling CIR mean level
`mu` and mean-reversion speed `theta`. Each observation date is fitted separately
across the eight maturities: **1, 2, 3, 5, 7, 10, 20 and 30 years**. The fitted
curve describes a parameter across maturities, not a new observed Treasury yield
curve. Sigma is passed separately through the [CURVE stage](../CURVE/readme.md).

## Run

Run from `Basel3_repo`, with the root requirements installed:

```bash
python3 -m pip install -r requirements.txt
python3 src/RWA/calibration/curves/mu.py
python3 src/RWA/calibration/curves/theta.py
```

These scripts have no command-line path options. `INPUT_FILE`, `OUTPUT_FILE` and
`MAX_WORKERS` are settings in each source file. Each command creates this output
directory if needed and replaces its corresponding output CSV. It does not
regenerate first-pass calibration or assemble the input curves.

## Inputs and outputs

| Parameter | Input under `RWA/Experimental/MLE YIELD/` | Output in this folder |
| --- | --- | --- |
| mu | `CURVE/mu_curve.csv` | `mu_curve_nss_repaired.csv` |
| theta | `CURVE/theta_curve.csv` | `theta_curve_nss_repaired.csv` |

Each input needs `observation_date` and eight named parameter columns, such as
`mu1y, mu2y, mu3y, mu5y, mu7y, mu10y, mu20y, mu30y`; the theta names use the same
maturities with the `theta` prefix. See [curve assembly](../CURVE/readme.md) for a
runnable preparation recipe. Keep dates unique for the downstream reconstruction.
The repair scripts retain row order and other input columns. Nonnumeric parameter
values are converted to missing values.

## Which nodes are repaired

| Script | Actual finite-value trigger | Boundary behavior |
| --- | --- | --- |
| [mu repair source](../../../../src/RWA/calibration/curves/mu.py) | `abs(mu) > 9` | Exactly +9 or -9 is not flagged |
| [theta repair source](../../../../src/RWA/calibration/curves/theta.py) | `abs(theta) < 0.01` | Exactly +0.01 or -0.01 is not flagged; zero is flagged |

Missing and infinite values are excluded from fitting and are not reconstruction
targets. Only flagged finite nodes are replaced. Nonflagged values are preserved,
so these triggers are not a complete validity check of every input parameter.

For each date with at least one flagged node:

1. Fit to the remaining finite, nonflagged maturities only.
2. With six or more usable maturities, use six-parameter Nelson–Siegel–Svensson
   (`curve_model = NSS`). With four or five, use four-parameter Nelson–Siegel
   (`curve_model = NS`). With fewer than four, retain the row and report failure.
3. Fit from multiple starting points with bounded SciPy `least_squares` and
   `soft_l1` loss; choose the successful fit with lowest ordinary squared error.
4. Evaluate that fitted curve at every flagged maturity. Before changing any
   node, require every proposed replacement to be finite and strictly positive.
   If any replacement fails, preserve all original parameter values for that row.

NS selection depends on the number of usable nodes. An unsuccessful NSS fit does
not automatically retry NS. Dates without flagged nodes skip optimization.
Anomalous dates use a process pool of at most `min(28, available CPUs, anomalous
rows)` workers; completed results are put back in the original row order.

## Read the audit columns

| Field | Interpretation |
| --- | --- |
| `curve_repair_performed`, `curve_fit_success` | True only when a repair was accepted; both remain false when no repair was needed or when it failed |
| `curve_fit_error` | Failure reason; empty for successful or unneeded repairs |
| `curve_model`, `curve_fit_rmse` | Accepted NS/NSS model and residual RMSE on its fit nodes |
| `anomaly_count`, `anomalous_maturities` | Number and names of flagged nodes before fitting |
| `<parameter><tenor>y_original` | Original numeric value, retained even after replacement |
| `<parameter><tenor>y_repaired` | Whether that particular node was replaced |

A process can finish and write its CSV while individual rows failed repair.
Review the printed failed-date summary and the audit fields. Use `anomaly_count`
to distinguish an unneeded repair from a failed one. Low RMSE does not by itself
establish sensible extrapolation or statistical identification.

The CSVs already checked into this folder are historical outputs and lack the
new `curve_fit_error` column. They were not regenerated by the code or README
changes. Newly generated files from the current scripts include that field and
the validation described above; do not label old data as newly validated.

## Next stage

After reviewing the repaired curves and ensuring mu/theta/sigma come from a
consistent calibration run, execute:

```bash
python3 src/RWA/data/parameters/rebuild.py
```

The [rebuild](../../../../src/RWA/data/parameters/rebuild.py) joins repaired
mu and theta, plus the unrepaired sigma curve, to each original yield file by
`observation_date`. It writes [MLE VOL/RAW](../../MLE%20VOL/RAW/readme.md).
Those six-column exports omit these audit fields, so retain the NSS files too.

The separate [endogenous hierarchy](../../../../src/RWA/models/parameter_hierarchy/readme.md)
uses coupled likelihood-budgeted ridge stabilization and fits processes to all
three parameter histories. Independent NS/NSS smoothing here is not that coupled
procedure and does not establish that weakly identified parameters were recovered.

## Verify

The focused tests exercise accepted and rejected repairs, whole-row preservation,
all eight maturities and the actual reconstruction consumer on isolated fixtures:

```bash
python3 -B -m unittest discover -s tests -p test_rwa_calibration.py -v
```

Use the [test guide](../../../../tests/readme.md) for repository-local temporary
and cache settings. Reading these instructions does not require running a repair
against the historical CSVs.
